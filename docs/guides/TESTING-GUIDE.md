# 测试规范与验收用例指南（TESTING-GUIDE）

**项目名称：** 听序（Tingxu）  
**文档版本：** v0.2  
**最后更新：** 2026-10-30  
**适用范围：** 单元测试、集成测试、音视频硬件模拟测试与系统验收测试  

---

## 1. 测试策略与分层要求

为保障听序在复杂桌面环境（多音响输出、蓝牙切换、系统权限撤销、异常断电）与高可靠云端交易场景下的鲁棒性，系统建立四层自动化与人工验收防线：

```
                 ▲
                / \     Level 4: 端到端与系统验收测试 (AC-001 ~ AC-016)
               /   \    Level 3: 音视频与系统权限集成测试 (WASAPI / SCKit / ASR)
              /     \   Level 2: 领域服务集成测试 (SQLite WAL, PG 事务, 微信回调)
             /       \  Level 1: 单元测试 (TDD 核心：增量切片算法、环形缓冲、状态机)
            ───────────
```

### 测试覆盖率指标
- 核心算法层（环形缓冲、滑动窗口切片、补丁合并）：**行覆盖率 $\ge 90\%$，分支覆盖率 $\ge 85\%$**；
- 账务与权益层（时长预占、结算、微信回调处理）：**行覆盖率 $100\%$**；
- UI 交互层：关键用户旅程（登录、录制、看板确认、导出）具备端到端测试覆盖。

## 2. 核心专项测试用例

### 2.1 录音与弱网异常专项
- **用例 T-AUDIO-01（断网录音高保真）**：在双轨录音运行至第 30 秒时，切断网络连接 60 秒后恢复。
  - **验收标准**：本地音频分片连续落盘，文件大小与采样率正常，无数据丢失；UI 字幕区提示“网络中断，云转写暂停”，联网后提供补转入口。
- **用例 T-AUDIO-02（设备热插拔）**：开会过程中拔除 USB 耳机，系统切换至内置扬声器。
  - **验收标准**：Rust 采集线程捕获设备变更事件，500ms 内平滑重建音频流，无 Panic，无刺耳爆音。

### 2.2 增量洞察与人工保护专项
- **用例 T-INSIGHT-01（人工编辑冲突保护）**：
  1. 洞察看板生成“建议周五发布”卡片；
  2. 用户手动点击“确认”；
  3. 输入后续 ASR 文本“刚才评估有误，必须推迟到下周一”；
  - **验收标准**：原卡片保持“已确认”与“周五发布”，右侧弹出修订审核弹窗，包含下周一依据，等待用户手工裁决，原卡片绝不被静默覆盖。

### 2.3 商业交易与防重放专项
- **用例 T-COMM-01（微信回调并发重放）**：
  - 模拟微信支付服务器向 `/payments/wechat/notify` 同时并发发送 5 次完全相同的支付成功通知。
  - **验收标准**：仅有一笔订单标记为 `PAID`，用户权益账户仅被充值一次套餐时长，其余 4 次返回 HTTP 200 并被幂等去重拦截。
